# Frame · AI 视频生成器

中文视频创作工作台，基于 React、Vite、Express 和 FFmpeg。支持提示词、创作会话记忆、长期偏好、四种画面风格、横竖屏、本地 2–60 秒时长、提示词时长识别、图片与视频参考模板、后台任务、MP4 下载与作品管理，适配桌面和手机。

## 在自己的电脑上免费运行真实模型

只想先看界面时，可以运行 `npm run preview:export`，然后直接用浏览器打开 `artifacts/Frame-preview.html`。这个独立 HTML 内嵌所有图片、脚本和样式，无需服务器、Node.js 或模型即可查看界面。可切换风格、参数、导航和弹窗；视频生成和 AI 润色明确禁用。聊天中的 localhost 网页卡片不能用作可分享的云端预览地址。

已增加 Ollama 提示词润色与 ComfyUI / Wan 2.1 本机视频生成接口，不需要付费 API token。针对 Windows 11、RTX 3060 Ti 8GB、16GB 内存准备了安装脚本和低显存参数。请先阅读 [Windows 本地部署说明](local/Windows本地部署.md)。该硬件从 512×288 / 288×512、2 秒视频开始，语言模型与视频模型错开运行。

```powershell
powershell.exe -NoProfile -ExecutionPolicy RemoteSigned -File .\scripts\setup-windows.ps1
npm.cmd run local:start
```

浏览器打开 `http://127.0.0.1:3001`，创作区默认选择“本地 Wan”和 2 秒。先在生成设置检查本机模型，再按画面描述生成；模型未就绪时界面会阻止提交，不会自动转成演示样片。`npm run local:check` 可报告工具与服务状态。下载模型需联网；生成使用本机算力，无付费 API 调用。接口与模拟流程已测试，真实 GPU 推理和画面与描述的一致性仍需在你自己的电脑验证。

## 快速运行

需要 Node.js 22+、npm 和带 `libx264` 编码器的 FFmpeg。当前云环境已安装所需工具。

```bash
cd /workspace/AI-video
npm ci
npm run dev
```

前端使用 5173 端口，后端使用 3001 端口；Vite 自动代理 `/api` 请求。开发模式后端端口请保持 3001。在其他机器中，可先用 `ffmpeg -version` 检查安装，Debian / Ubuntu 可通过系统包管理器安装 `ffmpeg`。

生产运行：

```bash
npm run build
npm start
```

生产服务默认监听本机 3001 端口，同时提供静态页面与 API。可通过 `PORT` 修改生产端口，通过 `HOST` 显式修改监听地址；本机部署保留 `127.0.0.1`。

`npm start` 现在会先自动构建前端（需要安装完整开发依赖）。开发模式使用 5173，生产模式使用 3001。如果出现 `Cannot GET /`，先停止旧进程，在项目根目录执行 `npm run build` 再执行 `npm start`，无需重装模型。`/api/health` 可查看应用标识和 `frontendReady` 状态；缺少构建文件时首页会显示修复命令。

## GitHub 连接失败时离线更新代码

GitHub Desktop 提示 `Failed to connect to github.com port 443` 表示连接 GitHub 超时。可以使用维护者提供的 `AI-video-offline-update-<提交>.zip` 更新已有仓库，无需重装 Python、PyTorch、Qwen 或模型。此方法更新本地代码，不会修复电脑到 GitHub 的网络连接。

1. 将整个 ZIP 解压到仓库外，例如 `D:\ai_video\offline-update`，停止正在运行的项目，再双击其中的 `start-update.cmd`。
2. 默认更新 `D:\ai_video\AI-video` 的 `codex/local-ai-video` 分支；其他安装位置可执行 `node .\apply-offline-update.mjs "你的仓库根目录"`。
3. 看到“离线更新成功”或“已经是更新包中的版本”即完成。网络恢复后在 GitHub Desktop 执行 Fetch origin，刷新远端状态。

更新需要已有 Node.js 22+ 和 Git 或 GitHub Desktop，无需管理员权限、npm 安装或 GitHub 联网。更新器自动查找 GitHub Desktop 内置 Git；检查仓库来源、当前分支、工作区、bundle 的 SHA-256 与提交关系，只允许快进更新。存在未提交改动、未结束的 Git 操作或本地独有提交时停止，不自动暂存、切换或重置。`.env`、`data/`、已下载模型及 `FrameRuntime` 保留；同名忽略文件冲突也会阻止更新。远端地址与 `FETCH_HEAD` 保持原样，GitHub Desktop 可能暂时显示旧的 origin 状态。

维护者在提交源码和 README 后运行 `npm run offline:export`，会在忽略的 `artifacts/` 下生成含完整分支 Git bundle、清单、独立更新器、Windows 启动器及中文说明的 ZIP。导出需要 Git、Node.js 和 Python 3（标准 ZIP 库）；使用更新包不需要 Python。导出会检查历史中常见的配置、模型和运行目录路径；分享前仍须检查历史内容，不应把路径检查视为完整的密钥扫描。清单内 SHA-256 用于完整性检查，并非独立数字签名。

## 生成模式

### 本地 Wan 2.1（默认，真实 AI，无 API 费用）

在自己电脑启动 ComfyUI 并安装 `local/models.json` 中的三个官方模型文件，选择“本地 Wan”。后端使用原生节点提交工作流、轮询任务历史并保存 MP4，无自定义节点依赖。本地默认 2 秒、33 帧；可选择 2–60 秒，较长成片会以最多 2 秒的片段串行生成，再由 FFmpeg 合成。模型采样阶段显示不确定进度，分段完成数按真实结果更新。生成失败不转向付费服务；服务重启后有任务编号或分段记录的未完成任务可继续恢复。

Ollama 的“本地 AI 润色”使用 `qwen3:4b`，要求保留用户主体与动作，以 JSON 的 `prompt` 字段输出 10–400 字的最终画面描述；关闭思考并检查输出结构、长度、常见分析文字及截断情况，拒绝将分析过程直接填入输入框。失败时保留原文，成功后可点击“撤销润色”；等待期间用户的新编辑也不会被旧请求结果覆盖。格式检查不能保证模型完全遵循语义，生成前仍需查看描述，也可跳过润色直接生成。

润色完成后 `keep_alive=0` 卸载语言模型。视频任务运行时禁止润色，润色前请求 ComfyUI 释放缓存。本机模型地址仅支持 HTTP loopback，默认分别为 `127.0.0.1:11434` 和 `127.0.0.1:8188`。

本机服务请求失败时，错误提示会区分连接拒绝、连接中断、超时与 HTTP 状态，并显示检测、提交工作流或查询任务等阶段；只保留允许的错误码，不回传原始异常、完整地址或响应正文。工作流被拒绝不会再被误报为服务未启动。任务提交后查询失败会提醒先看 ComfyUI 控制台和队列，避免重复提交。若控制台在 `got prompt` 和模型加载日志后直接回到 PowerShell，说明生成进程已退出；应先在同一窗口读取 `$LASTEXITCODE`，再结合崩溃日志排查，不能仅凭最后一条 FP8 信息就认定是显存不足。详细步骤见 [Windows 本地部署说明](local/Windows本地部署.md)。

### 时长选择与长视频

创作区可选择 2、4、6、8、12、20、30、60 秒，或选择“根据提示词识别”，每次生成一个版本。提示词可写“总时长十二秒，展示皮秒设备……”“生成一个 8 秒的视频……”或“时长一分钟”。API 支持本地与演示模式 2–60 秒整数；Sora 仍只支持 4、8、12 秒。自动识别没有明确目标、包含冲突时长或超出范围时，会要求调整，不会静默使用 2 秒。明确总时长优先于镜头或源模板时长；润色会保留原始目标时长。

为控制单次显存占用，本地长片由独立短片组成，例如 5 秒对应 2＋2＋1 秒。每段都提交真实生成请求，不用循环播放或放慢一段视频凑时长；合成为 16fps、无音轨的 MP4，并校验总时长。各段仍是独立文生视频，人物外观、动作和镜头衔接可能变化，不能保证连续剧情一致。任务越长，生成耗时和磁盘占用越多；应先验证本机 2 秒真实生成正常，再尝试长片。此功能不解决已有的 PyTorch 原生崩溃。

分段文件保存在 `data/segments/<任务ID>/`，记录每段任务编号与完成状态。服务在任务处理中重启时，可复用已校验片段并继续查询已提交的任务；生成或合成失败会保留片段，不自动重复提交。网页的“重新生成”会新建任务，不能替代恢复原任务。删除作品会同时删除该任务的分段文件。

### 图片与视频参考模板

左侧“参考模板”支持上传图片或视频，分析并保存摘要、场景、人物可见外观、物体与设备、风格、镜头和动作七项描述。分析需要额外的本机视觉模型，文字模型 `qwen3:4b` 无法直接读图：

```powershell
ollama pull qwen2.5vl:3b
```

默认模型可通过 `.env` 的 `TEMPLATE_VISION_MODEL` 修改，模型必须报告视觉能力。安装后在“生成设置”重新检测，进入模板页上传素材，选择“分析模板”，检查或编辑结果后保存，再点击“用于创作”。也可手动填写和保存参考描述。创作区可选一个已就绪模板，并勾选场景、人物、物体、风格、镜头或动作。实际生成会加入选中的描述；演示模式会明确拒绝模板参考，避免把内置照片当成学习结果。

这是参考内容提取与文字条件生成：不训练或修改模型权重，不能保证同一人物、服装、物体或全部场景完全复现。视频均匀抽取最多 6 帧，分析帧最大边长 512 像素以控制视觉模型占用，不分析声音，也不能覆盖全部动态和细节。分析结果需人工检查。支持 JPEG、PNG、WebP、MP4、MOV、WebM；单文件最多 100 MiB，视频最多 300 秒，图片最大边长 8192、最多 4000 万像素，每个库最多 20 个模板。

素材、缩略图和描述保存在本机忽略目录 `data/templates/<模板ID>/`；FFmpeg/FFprobe 做真实媒体验证与画面提取，视觉模型仅通过本机 Ollama 接收 JPEG 帧。分析与视频生成、提示词润色互斥，分析前释放已有模型，完成后卸载视觉模型。缺模型或分析失败时会显示失败，不虚构学习结果；原素材与已有描述保留，重启中断的分析可重试。删除模板会删除其素材和描述；已有作品保留当次使用的参考描述快照，删除作品可移除该快照。选择 Sora 时会像普通提示词一样向其发送选中的参考文字，原始素材不会由此上传。

### 创作记忆与上下文

创作区默认开启“使用上下文记忆”。先在一个会话里描述主体、场景和动作，下一次可输入“把背景换成夜景”“保持时长，镜头拉近”等简短要求。润色会读取当前会话的近期历史；生成时如已有上下文，会先通过本机 Qwen 整理成可独立使用的完整画面描述，再提交给所选生成模型。第一次仍需完整描述；有上下文时可输入至少 2 个字符的跟进要求。当前要求和界面明确选择的参数优先于历史及长期偏好。自动时长模式可从整理后的描述继承该会话之前的总时长，存在冲突时会报错。演示模式仍只对内置图片运镜，不按上下文生成画面。

通过“新会话”开始不同主题，或在左侧“创作记忆”查看、切换、重命名和删除会话；不同会话的近期描述不会混用。可手动保存最多 1000 字的“长期创作偏好”，它适用于所有会话；偏好不会从聊天中自动推断为永久事实。切换会话会恢复其最近整理描述与已保存参数；刷新后保留选中的会话，并恢复已有创作参数，但不覆盖你正在编辑的输入。原有“新建视频”清空当前输入，仍属于当前会话；新主题需显式“新会话”。

成功返回的润色建议、已提交的生成要求及其整理描述会保存在 `data/memory.json`。生成记录会标明提交、完成或失败，服务重启时会与已有任务核对状态，且不重建已清除的记忆；这些是文字要求与任务状态，不代表 AI 看过成片，也不训练模型权重。最多保存 20 个会话，每个会话保留最近 30 条；实际送入模型的历史最多 4 条，长期偏好与历史文本按 2400 字预算裁剪，优先保留最近完整描述。该预算和有限模型能力意味着不能保证记住所有细节；重要偏好可手动维护，生成前可查看“本次实际画面描述”。

“撤销润色”以及等待期间被编辑或拒绝采用的结果，会尝试移除对应建议记录；网络或保存失败会提示去记忆页检查。模型调用失败不会新增建议或生成任务。生成已提交后发生渲染失败仍保留该次要求并标记失败。历史失败任务的“重试生成”使用原任务整理描述，不套用当前另一个会话的记忆。

可关闭自动记忆，或逐条删除、清空当前会话、清除全部会话及偏好。清空与删除有确认；停用后润色和生成不向模型传入历史或新增会话记录，既有内容仍可管理。新建或切换会话完成前会暂停输入，防止等待期间的新内容被覆盖。模型请求中途清除、删除、重命名会话或修改偏好时，旧版本结果会被拒绝写回，避免恢复已清除的内容；切换会话后迟到的生成结果只进入作品库，不强行打开到新会话。清除记忆不删除已有作品或已提交任务的描述快照，删除作品也不自动删除其会话记录。

此功能复用已有 `qwen3:4b`，无需新模型。上下文整理与视频生成、模板分析串行使用本机模型；有历史的生成请求可能额外等待一次语言模型调用，忙碌或失败时会明确提示。默认请求只在本机处理；若主动选择 Sora，整理后的最终描述会像普通提示词一样发送给该服务。记忆来源为当前会话的创作要求、整理结果和手工偏好，保存在本机单用户数据目录。独立 HTML 预览不读取或保存记忆。

### 演示模式（手动选择，无需密钥）

FFmpeg 将所选风格的内置照片处理为缓慢推近、带淡入淡出的 H.264 MP4，实际应用所选比例和时长。**演示模式不会理解提示词，也不会调用 AI 模型；它不是文生视频的真实 AI 输出。**必须手动选择此模式，界面会明确说明“内置照片运镜，不按提示词生成”，新建或重试演示任务都需再次确认。界面、任务记录与作品卡片均标明“演示样片”。

输出为 1280×720 横屏或 720×1280 竖屏，24 fps，无音轨。此模式用于完整体验生成、播放和下载流程。

### OpenAI Sora 2（配置后可用）

复制 `.env.example` 为 `.env`，在本机安全编辑并填入自己的密钥：

```dotenv
VIDEO_API_KEY=你的_OpenAI_API_密钥
```

重启服务器，在“生成模式”中选择 Sora 2。也支持服务器已有的 `OPENAI_API_KEY`，优先使用非空 `VIDEO_API_KEY`。密钥仅供后端调用，不返回前端，不应放在 `VITE_*` 变量或提示词中。`.env` 已被 Git 忽略。

实现使用官方 `POST /v1/videos` multipart 接口、`GET /v1/videos/:id` 轮询和 `GET /v1/videos/:id/content` 下载。模型为 `sora-2`，时长为 4 / 8 / 12 秒，尺寸为 1280×720 / 720×1280；风格以英文视觉指导附加到提示词。保留环境提供的 HTTPS 代理与 TLS 校验。

实际 AI 调用需要账户具备视频接口权限、足够额度，以及访问 `api.openai.com` 的网络权限，可能按服务商规则计费。当前版本未配置密钥，所以**真实模型生成尚未进行在线验证**；接口适配器的成功与失败路径通过模拟响应测试。未配置密钥时，AI 请求明确失败，不会退回演示模式。

## 数据与任务

- `data/jobs.json` 保存任务元数据，原子替换写入；`data/<任务 UUID>.mp4` 保存成片。部署时请将 `data/` 挂载为持久卷并备份。
- `data/templates/` 保存本机参考素材与描述，`data/segments/` 保存长片分段及恢复所需文件；都属于运行数据，不提交 Git。
- `data/memory.json` 保存创作会话和长期偏好，原子替换写入；损坏或不兼容时会保留原文件并报错，需先备份检查，不会静默重置。
- 单个服务器串行生成任务，最多 5 个待处理任务和 100 条历史记录。视频只在本机保存，不上传第三方存储。
- 浏览器刷新或离开页面不影响后台任务；在“我的作品”可找回记录。服务重启后，已取得远端 ID 的 Sora 任务会继续轮询，本地未完成的演示任务标为失败，可手动重新生成。
- 删除作品同时删除本地视频与记录；活动任务不可删除。失败任务可重试，重试 AI 生成可能创建新的付费任务。
- 此版本为单用户工作台，不提供登录或用户隔离。对外部署前，应在网关添加认证和访问限制，尤其是已配置付费密钥的服务。不要启动多个实例共同写入同一个 JSON 存储。
- 图生视频、声音编辑与多镜头剪辑不在当前版本范围内。


API 测试会实际生成横竖屏视频，通过 FFprobe 验证 H.264、尺寸与时长，同时检查视频流范围请求、下载、删除、参数校验、失败状态、重启恢复和模拟 Sora 接口。新增测试覆盖中文与英文时长解析、独立分段合成与恢复、真实媒体处理、模板参考和视觉接口传图，以及记忆持久化、会话隔离、上下文预算、停用、短跟进生成与清除后迟到结果拒绝。云端没有执行真实 Wan、Qwen 或视觉模型推理，不代替目标电脑的画面质量、显存和稳定性验证。UI 测试使用系统 Chromium（默认 `/usr/bin/chromium`），覆盖生成和作品管理、模板与自动时长、会话及偏好保存、润色撤销移除记忆、会话切换、刷新参数恢复、迟到结果和历史重试，以及移动端与独立预览。可通过 `CHROMIUM_PATH` 和 `TEST_BASE_URL` 覆盖浏览器路径与测试地址。

UI 测试创建带独立标记的测试作品，流程完成后仅删除该作品；API 测试使用独立临时目录，不修改开发作品。

Windows 安装器在 Winget 下载 FFmpeg 失败时，会使用带固定 SHA-256 校验的官方 essentials ZIP 作为备用来源，也支持手动指定已下载的 ZIP。可运行 `powershell.exe -NoProfile -ExecutionPolicy RemoteSigned -File tests/ffmpeg-installer.tests.ps1` 验证错误校验值会在解压和修改 PATH 前被拒绝，并保留已有文件。该检查不安装真实工具；Windows 安装与网络连通性仍须在目标电脑验证。

ComfyUI 源码克隆使用单次命令级 HTTP/1.1 和 TLS 校验，并最多重试三次；每次在新目录下载，验证固定提交后启用，已有不完整目录会备份保留。可运行 `powershell.exe -NoProfile -ExecutionPolicy RemoteSigned -File tests/comfy-source.tests.ps1` 验证连接失败重试、旧文件保留、固定提交检查和重试上限；测试模拟 Git 传输，不下载模型。

Python 依赖安装默认使用官方 PyPI，下载超时为 120 秒、最多重试 5 次。网络缓慢时可在 Windows 安装命令中增加 `-PipIndexUrl "https://pypi.tuna.tsinghua.edu.cn/simple"`，仅为 pip 升级和 ComfyUI 普通依赖选择 HTTPS 镜像，不修改全局 pip 配置；PyTorch 仍使用官方 CUDA 12.8 源，已安装的指定 CUDA 包会直接复用。安装器显式补充 ComfyUI 启动使用的 `requests>=2.32.5,<3`，不修改 ComfyUI 原始依赖清单；安装后运行 `pip check` 和 `import requests` 检查，随后检查 CUDA。`pip check` 只检查包声明的依赖关系，不能证明源码使用的模块都已声明或可以导入。详细恢复步骤见 [Windows 本地部署说明](local/Windows本地部署.md)。`tests/python-deps.tests.ps1` 使用模拟 pip 验证包源选择、CUDA 复用、失败处理、requests 导入检查及依赖文件保留，不安装真实模型。

已有环境启动时报 `ModuleNotFoundError: No module named 'requests'` 时，可先在正在启动的终端按 `Ctrl+C`，再只为 ComfyUI 虚拟环境补装并检查：

```powershell
& "D:\ai_video\FrameRuntime\ComfyUI\.venv\Scripts\python.exe" -m pip install "requests>=2.32.5,<3" --index-url "https://pypi.tuna.tsinghua.edu.cn/simple" --timeout 120 --retries 5
& "D:\ai_video\FrameRuntime\ComfyUI\.venv\Scripts\python.exe" -c "import requests; print(requests.__version__)"
```

补装成功后执行 `npm.cmd --prefix "D:\ai_video\AI-video" run local:start`。这里使用清华 TUNA PyPI 镜像；也可将索引换为官方 `https://pypi.org/simple`。该恢复步骤不重新安装 PyTorch 或下载模型。

Wan 下载器现在显示经过脱敏的底层网络错误码，每个文件最多尝试 3 次，并从 `.part` 分片继续。默认端点仍是官方 Hugging Face；可用 `--endpoint https://hf-mirror.com` 显式选择第三方 HF-Mirror，或用 `--from-dir` 导入已下载的同版文件。无论从哪里取得文件，均使用 `local/models.json` 中原有的大小、固定版本和 SHA-256 校验，校验成功后才启用，不读取 Hugging Face token。`HF_ENDPOINT` 也可指定默认下载端点；完整 Windows 安装脚本使用 `-ModelEndpoint` 参数。仅下载模型不需要重新安装 Python、PyTorch 或 Qwen。

`node --test tests/offline-update.test.js` 使用临时 Git 仓库和真实 bundle 验证快进更新、重复执行、配置和数据保留，以及脏工作区、错误分支、提交分叉、旧包回退和包损坏时拒绝更新。测试不连接 GitHub；Windows 启动器仍需在目标电脑验证。

```text
shared/duration.js   前后端共用的时长解析与范围校验
src/TemplateLibrary.jsx  参考模板上传、预览和描述编辑界面
src/MemoryPanel.jsx  记忆开关、会话管理、长期偏好与历史查看
scripts/python-deps.ps1  Python 依赖安装、下载重试和包源选择
scripts/download-models.mjs  Wan 模型续传、端点选择和校验导入
scripts/offline-update.mjs  从本地 Git bundle 安全快进已有仓库

tests/               API 集成测试和浏览器流程测试
```
